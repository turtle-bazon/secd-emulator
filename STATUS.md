# SECD Emulator — Current State

## What works

- **VM core** (`src/vm/`): full SECD interpreter, all opcodes, boxed wide
  integers (LDCW + BIGNUM), bignum arithmetic primitives (%bn-*)
- **Binary**: `build/secd-emulator` via ASDF program-op (clingon CLI)
- **Device catalog**: 12 boards embedded from secd-machine/targets/
- **Standalone HTTP test** (`standalone-test.lisp`): verified serving
  /api/devices with all 12 boards over plain HTTP (no WS needed)

## WebSocket dispatch failure

### Root cause: BUGGY EMULATOR CODE, not library limitations

Clack + Wookie + websocket-driver is **PROVEN WORKING** for bidirectional
WebSocket communication. Verified by `/tmp/opencode/ws-echo-test.lisp`:
101 handshake ✓, client sends JSON ✓, server receives via :message hook ✓,
echoes back ✓, client receives echo ✓.

Focus project (github.com/turtle-bazon/focus) uses the identical stack
in production.

The secd-emulator WS failure was caused by:
1. `(ignore-errors ...)` wrapping handle-message calls — silently
   swallowing all real errors from broken JSON encoding and undefined
   variable references (*current-session*)
2. Broken JSON encoding functions produced by repeated Python string
   escaping surgery on server.lisp (wrong quote/backslash counts)
3. Accumulated structural damage to server.lisp from incremental edits
   (paren imbalance, stale fasls, package mismatches)

**Rule: NEVER silence errors.** All errors must propagate loudly.
Silenced errors hide real bugs and make debugging impossible.

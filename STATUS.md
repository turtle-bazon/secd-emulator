# SECD Emulator — Current State

## What works

- **VM core** (`src/vm/`): full SECD interpreter, all opcodes, boxed wide
  integers (LDCW + BIGNUM), bignum arithmetic primitives (%bn-*)
- **Binary**: `build/secd-emulator` via ASDF program-op (clingon CLI)
- **Device catalog**: 12 boards embedded from secd-machine/targets/
- **Standalone HTTP test** (`standalone-test.lisp`): verified serving
  /api/devices with all 12 boards over plain HTTP (no WS needed)

## Known issues (deferred)

### WebSocket dispatch broken under Wookie
- `websocket-driver:websocket-p env` returns truthy for upgrade requests
- `make-server` + hooks register successfully, responder returned
- BUT: after the 101 handshake, wookie's fast-http parser still owns
  the socket read side and rejects WS frames with INVALID-METHOD
- Root cause: clack-handler-wookie doesn't hand read-callback ownership
  to websocket-driver's frame parser post-upgrade
- Evidence: echo test (`ws-echo-test.lisp`) gets 101 and server→client
  sends work, but client→server frames never reach :message hook
- Focus project works because its WS is server→client broadcast only;
  it never reads messages from clients over WebSocket

### Possible fixes (not yet attempted)
1. After start-connection, replace wokie's read-callback on the
   cl-async socket to feed bytes directly to websocket-driver's parser
2. Use raw wokie defroute with :websocket t (bypassing clack entirely)
3. Switch to Hunchentoot (:server :hunchentoot) which has proven
   websocket-driver integration through clack-handler-hunchentoot

## File layout

- `standalone-test.lisp` — minimal HTTP API test (proven working),
  run: sbcl --load standalone-test.lisp → http://localhost:8899/api/devices
